# Minimal Market

Минималистичный маркетплейс в духе WB и Ozon: покупатели, продавцы и администратор.

**Демо:** [https://minimal-market-ten.vercel.app](https://minimal-market-ten.vercel.app/)

## Роли

| Роль | Как получить | Что доступно |
|---|---|---|
| Гость | без регистрации | каталог, поиск, фильтры, корзина и избранное (хранятся в `localStorage`) |
| Покупатель | регистрация | корзина и избранное в базе, заказы и оплата, отзывы, жалобы |
| Продавец | роль выдаёт только администратор | управление своими товарами, остатками и заказами, статистика |
| Администратор | назначается только через SQL | жалобы, продавцы, категории, все заказы |

## Возможности

### Каталог и поиск

- поиск по названию, бренду и категории;
- фильтры: категория (со счётчиками), диапазон цены, «только в наличии»;
- сортировка: новые, дешёвые, дорогие;
- пагинация по 12 товаров;
- состояние каталога хранится в адресе (`/?category=...&sort=...&page=2`), поэтому ссылкой на подборку можно делиться.

### Карточка товара

- название, бренд, артикул (`MM-000001`), цена и остаток;
- старая цена показывается, только если она больше текущей;
- галерея фотографий и название магазина продавца;
- средний рейтинг и отзывы;
- кнопка жалобы на товар;
- если товара нет в наличии, кнопка «В корзину» блокируется.

### Корзина и избранное

- гость работает с `localStorage`;
- после входа данные переносятся в аккаунт: для корзины берётся большее количество, для избранного объединение;
- дальше всё хранится в базе и синхронизируется между устройствами;
- количество в корзине ограничено остатком на складе.

### Заказы

- заказ создаётся одной SQL-функцией: она атомарно блокирует товары, проверяет остатки и статусы, считает сумму по текущим ценам, создаёт заказ с позициями, списывает остатки и очищает корзину;
- цена «живая»: если она изменилась, пока покупатель оформлял заказ, функция отказывает, и покупатель подтверждает новую сумму;
- оплата пока имитируется; отмена возможна до оплаты, остатки при этом возвращаются на склад;
- статусы: создан → оплачен → собран → отправлен → доставлен, а также отменён;
- страница «Мои заказы» с составом, адресом, телефоном и суммой.

### Кабинет продавца

- публикация товара: название, категория, бренд, цена, остаток, описание и фото (JPG, PNG или WebP до 5 МБ);
- редактирование цены, старой цены, остатка и статуса (активен, черновик, скрыт);
- заказы на свои товары: статус хранится у каждой позиции, а общий статус заказа пересчитывается автоматически, потому что в одном заказе могут быть товары разных продавцов; продавец двигает статус только вперёд на один шаг;
- статистика: выручка, проданные штуки, число заказов, средний чек, лучшие товары и товары с низким остатком (не больше 3 шт.).

### Отзывы и рейтинги

- отзыв может оставить только тот, у кого есть доставленная позиция этого товара (проверяет база, а не интерфейс);
- свой товар оценивать нельзя, один отзыв на товар от одного человека, отзыв можно изменить и удалить;
- рейтинг и число отзывов пересчитываются триггером и защищены от ручной правки.

### Админ-панель

- **Жалобы** на товары и отзывы: скрыть товар, удалить отзыв, отметить решённой или отклонить; дублирующие открытые жалобы запрещены;
- **Продавцы:** выдача и снятие роли, название магазина;
- **Категории:** добавление, переименование, удаление (удаление категории с товарами защищено от ошибки);
- **Все заказы:** последние 200.

## База данных

10 связанных таблиц и бакет Storage `product-images`.

| Таблица | Назначение |
|---|---|
| `profiles` | профили и роли пользователей |
| `categories` | категории |
| `products` | товары |
| `product_images` | фотографии товаров |
| `favorites` | избранное |
| `cart_items` | корзина |
| `orders` | заказы |
| `order_items` | позиции заказов |
| `reviews` | отзывы |
| `reports` | жалобы |

Безопасность и целостность данных:

- **RLS** включён на всех таблицах; заказы и роли нельзя изменить напрямую из браузера, только через функции;
- **ограничение колонок** (column-level grants): пользователь не может сам стать продавцом или администратором и не может накрутить рейтинг;
- **SQL-функции** (`security definer`): `create_order`, `pay_order`, `cancel_order`, `seller_set_item_status`, `can_review`, `admin_list_users`, `admin_set_seller` и вспомогательные `is_admin`, `is_seller`, `is_order_seller`;
- **триггеры:** автосоздание профиля при регистрации, обновление `updated_at`, пересчёт рейтинга;
- **валидация на уровне БД:** `check`-ограничения, `unique`, внешние ключи с продуманным каскадом;
- **хранилище фото:** публичный бакет, до 5 МБ, JPG, PNG или WebP; загружать могут только продавцы и только в свою папку; файлы удаляются вместе с товаром.

## Запуск локально

1. Установите [Node.js](https://nodejs.org) (LTS-версия).
2. Склонируйте репозиторий и установите зависимости:

   ```bash
   git clone https://github.com/aidar0x/minimal-market.git
   cd minimal-market
   npm install
   ```

3. Создайте проект на [supabase.com](https://supabase.com) и выполните SQL из файла
   `supabase/schema.sql` (раздел **SQL Editor**).
4. В Supabase откройте **Authentication → Sign In / Providers → Email** и на время
   разработки отключите **Confirm email**. Для продакшена подтверждение почты лучше включить: интерфейс его поддерживает.
5. Скопируйте `.env.example` в `.env.local` и вставьте свои значения из
   **Project Settings → API**:

   ```text
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=your_public_anon_key
   ```

   > Файл `.env.local` находится в `.gitignore` и не должен попадать в репозиторий.

6. Запустите проект:

   ```bash
   npm run dev
   ```

   Сайт откроется на `http://localhost:5173`.

### Как создать администратора

Роль администратора назначается только через SQL. Зарегистрируйте пользователя на сайте, затем выполните в **SQL Editor**:

```sql
update profiles set is_admin = true
where id = (select id from auth.users where email = 'you@example.com');
```

Роль продавца после этого выдаётся в админ-панели, на вкладке «Продавцы».

## Деплой и CI/CD

Репозиторий подключён к Vercel: каждый push в основную ветку автоматически собирает и публикует новую версию сайта, а для остальных веток создаются предпросмотры. В настройках проекта на Vercel заданы переменные окружения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Файл `vercel.json` перенаправляет все адреса на `index.html`, чтобы работал React Router.
